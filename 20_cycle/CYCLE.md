# CYCLE — El motor de trabajo

> La operación (Semilla B1) hecha ciclo. La teoría del método vive en los
> estratos externos (development-system: SYSTEM_DESIGN_METHOD, DESTILADO);
> aquí solo lo que este entorno exige para operar. Este documento no repite
> lo que la ley ya fija.

## El ciclo

```
idea (≤5 líneas, sin solución)
→ diseño y contratos (método de 12 etapas, estrato externo)
→ auditoría adversarial (modelo distinto — LAW §8)
→ congelar
→ rebanada vertical (criterio binario)
→ refutación → ADR → corrección
→ cierre:  Clase M → DEPOSITS.md
           Clase O → VALUE_EVENTS.md
→ las seis preguntas (VOICES.md) antes de declarar cerrado
```

Precedencia entre ciclos: LAW §4 (refutaciones primero, siempre).

## Route — quién ejecuta (del skill route, sin alteración)

- **Tipo 1** creación nueva → modelo (tier mínimo que funcione, prompt denso).
- **Tipo 2** operación de capacidad existente → operador con runbook, cero
  modelo. Si el runbook no existe, ese es el defecto.
- **Tipo 3** verificación con ojos/oídos/teléfono → operador, siempre.
- **Tipo 4** registro y marcado → operador, con su editor.

El token no gastado es el mejor. Derivación material: DEVELOPMENT.md — runway
finito; la economía de route no es preferencia, es supervivencia.

## Regla del runbook

Toda capacidad nueva termina con su runbook ejecutable sin modelo, en
`runbooks/` de la línea correspondiente. Un entorno que solo opera con IA
crea dependencia del externo — exactamente lo que el Activador prohíbe.

## Sesiones de modelo

Ninguna sesión escribe sin envelope completo (`OPERATOR.md`). El estado del
trabajo se lee de los ledgers y las líneas, nunca de la memoria de una
conversación. El método no se opera con memoria; se opera con lectura.
